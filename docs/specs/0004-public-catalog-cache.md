# 0004. كاش صفحات الكتالوج العامة

**Date**: 2026-11-08
**Status**: In Progress

## Summary

يخزن التطبيق بيانات العرض المستخدمة في قوائم المنتجات والبحث وصفحات المنتج والتصنيف لمدة ساعة. تبطل تغييرات المنتجات والتصنيفات كاش الكتالوج فورًا، ويستمر الموقع بالعمل من قاعدة البيانات عند تعطل مخازن الكاش.

## Context

تستخدم البيئة المحلية كاش الملفات، والإنتاج Upstash Redis عبر Predis مع مخزن Laravel الاحتياطي إلى الملفات. يجب أن تعمل آلية الكاش والإبطال مع كلا المخزنين، وأن تبقى المشاهدات صحيحة عند إعادة استخدام بيانات الصفحة المخزنة.

## Requirements

- **AC-1**: تخزن بيانات العرض للصفحات العامة لقوائم المنتجات، ونتائج البحث والفلاتر، وتفاصيل المنتج، وصفحات التصنيف لمدة 60 دقيقة.
- **AC-2**: يتضمن مفتاح نتائج القائمة اللغة، واستعلام البحث، والفلاتر، والترتيب، ورقم الصفحة أو مؤشرها، وأي مدخل آخر يغير النتيجة.
- **AC-3**: يسجل كل طلب لصفحة منتج منشور مشاهدة مستقلة، حتى عند تقديم بيانات الصفحة من الكاش. يبقى تسجيل النقرة مستقلًا عن كاش الصفحة.
- **AC-4**: بعد نجاح تعديل أو نشر أو إخفاء منتج، أو تعديل أو نقل أو إعادة ترتيب أو تعطيل تصنيف، تصبح بيانات الكتالوج المخزنة غير قابلة لإعادة الاستخدام في الطلبات التالية.
- **AC-5**: عند فشل إبطال الكاش، يتجاوز التطبيق الكاش ويقرأ من قاعدة البيانات إلى أن ينجح الإبطال.
- **AC-6**: عند تعذر Redis ومخزن الملفات معًا، يتجاوز التطبيق الكاش ويستمر بخدمة الطلب من قاعدة البيانات.
- **AC-7**: لا تعرض الصفحات العامة منتجات مخفية أو تصنيفات غير نشطة، حتى عند وجود مدخلات كاش سابقة.

## Decision

**Chosen option**: استخدام Laravel Cache مع مخزن `failover` المعتمد، وتخزين بيانات العرض بمفاتيح إصدار قابلة للإبطال.

تستخدم القوائم والبحث إصدارًا عامًا للكتالوج في فضاء المفاتيح. يؤدي تعديل منتج أو تصنيف إلى تغيير الإصدار بعد نجاح المعاملة، فتُهمل نتائج القوائم القديمة. تخزن صفحة المنتج وصفحة التصنيف بمفتاح يتضمن معرّف السجل واللغة والإصدار الملائم. لا تعتمد الآلية على Cache Tags، كي تعمل مع مخزن الملفات الاحتياطي. تسجل المشاهدة خارج قيمة الكاش في كل طلب.

## Feature design

**Cache boundaries**:
- يخزن الكاش بيانات العرض اللازمة للرندر، لا استجابة HTTP كاملة، كي ينفذ التطبيق تسجيل المشاهدة ويفرض حالة النشر في كل طلب.
- مفتاح بيانات المنتج يتضمن معرّف المنتج واللغة وإصدار بياناته. مفتاح التصنيف يتضمن معرّف التصنيف واللغة وإصدار الكتالوج.
- مفتاح القائمة يتضمن إصدار الكتالوج وبصمة معيارية لكل مدخلات البحث والفلترة والترتيب والتقسيم إلى صفحات واللغة.
- تحفظ المفاتيح ساعة. عند إعادة البناء تحفظ القيمة 60 دقيقة من وقت بنائها.

**Invalidation**:
- بعد التزام معاملة تعديل المنتج، يرفع التطبيق إصدار الكتالوج وإصدار المنتج.
- بعد التزام معاملة تعديل التصنيف أو شجرته، يرفع إصدار الكتالوج وإصدارات التصنيفات المتأثرة.
- لا يبطل الكاش قبل التزام قاعدة البيانات.
- إذا فشل تغيير الإصدار، تسجل المشكلة ويقرأ التطبيق الطلبات العامة مباشرة من قاعدة البيانات حتى يستعيد مخزن الكاش عمله. لا يقدم قيمة قديمة على أنها حديثة.

**Failure behavior**:
- عند فشل القراءة أو الكتابة في مخزن الكاش، يستمر الطلب بقراءة قاعدة البيانات.
- لا يعتمد التطبيق على الكاش لصحة الصلاحية أو الحالة أو تسجيل الأحداث.
- تسجل أخطاء الكاش دون تسجيل بيانات شخصية أو محتوى حساس من الطلب.

## Build plan

1. إضافة واجهة كاش للبيانات العامة مع مفاتيح معيارية للغة والبحث والفلاتر والترتيب والصفحات، يحقق **AC-1** و**AC-2**.
2. ربط تسجيل المشاهدة بطلب صفحة المنتج خارج قيمة الكاش، يحقق **AC-3** و**AC-7**.
3. إضافة إصدارات الكتالوج والسجلات وإبطالها بعد معاملات المنتج والتصنيف، يحقق **AC-4** و**AC-5**.
4. معالجة فشل مخازن الكاش والانتقال للقراءة المباشرة، يحقق **AC-6**.

## Consequences

**Positive**:
- يخفض تكرار قراءة استعلامات العرض مع الحفاظ على الأحداث لكل طلب.
- يعمل الإبطال مع Redis والملفات دون الاعتماد على دعم وسوم الكاش.

**Negative / tradeoffs**:
- الإصدار العام يبطل نتائج البحث كلها عند أي تغيير، حتى النتائج غير المتأثرة.
- تعطل الكاش يرفع حمل القراءة على قاعدة البيانات، لذا تظل الفهارس مهمة.
- لا يخزن هذا القرار استجابة HTML كاملة، لذلك لا يلغي تنفيذ Laravel لكل طلب.

## Rationale

الإبطال العام أبسط من تتبع كل مجموعة مفاتيح بحث، ويتناسب مع بداية صغيرة. مدة الساعة تقلل إعادة بناء الاستعلامات، بينما يحقق تغيير الإصدار ظهور التعديلات في الطلب التالي. تخزين بيانات العرض بدل HTML يسمح بتسجيل مشاهدة كل طلب.
